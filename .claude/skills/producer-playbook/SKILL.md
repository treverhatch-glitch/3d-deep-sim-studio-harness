# Producer playbook (items 12 to 20 of the Producer kickoff, moved here in 2.30g so the kickoff stays short)

12. Keep the studio running when nobody is watching: `npm run studio:start -- --until 23:00 [--budget 50%] [--lanes auto]` (or `--install` so it comes back after a restart). It keeps the War Room up and starts a fresh agent per task. Give tasks a lane (`task add … --lane game/<game>/src/floors`) so builders work in parallel without sharing a folder, and split big renderer files early (studio/rules/lanes.md). `npm run budget` shows each tool's plan use against its target.
13. Progress is by phase: when a phase opens, write studio/bible/PHASE-<n>-EXIT.md as a checklist ("- [ ] floors 1-3 playable start to win"), tick items as they're proved, and queue the next phase's tasks with --phase so it doesn't read "not planned".
14. The art department works in the Asset studio (War Room view 4): rounds don't wait for the dev, and you approve provisionally when they're slow. The Arcade (view 5) plays the last good build: point the dev there when they ask to play.
15. You staff the studio. Open a department when the work needs it (`npm run division -- open sound --reason "…" --by $STUDIO_LOCK_OWNER`), then hire into it: `npm run agent -- hire --role sound-designer --division sound --next --by $STUDIO_LOCK_OWNER [--note "…"]`. You may hire up to the limit in studio/budget.json (producerMayHireUpTo); past it the hire becomes a question for the game dev. Pause an agent on the wrong work with `npm run agent -- pause <name> --note "…"`. Close departments that have nothing left to do.
16. If the Dev Hacker Lab is open, a "Tricks:" task brings the dev hacker's cards (`npm run trick -- list`). Adopt a card only when it names a problem this game really has and a way to prove it helped (`npm run trick -- adopt K-001 --by $STUDIO_LOCK_OWNER --phase 1 --serves pillar:<p>`); park the rest with a reason. Nothing waits on the lab.
17. Cheat sheet check: when you plan or queue, `npm run cheatsheet -- match "<plan>" --for director` first. Before you hand out a task, `npm run cheatsheet -- attach <ID> --by $STUDIO_LOCK_OWNER` attaches up to 3 matching tricks to its brief as pre-approved for that task (recorded; one file read, no wait). Anything else the agent wants still follows the approval rules.
18. Agents refresh their context at the task boundary or ~120k tokens / 40 turns (`npm run session`). A "Check <agent>" ask means one is past that point, flagged mid-debug or not: `npm run session -- check <agent> continue|handoff --by $STUDIO_LOCK_OWNER`.
19. Work that must wait for other work says so: `--after T-146` when you add it, or `npm run task -- block <ID> --until T-146 --by $STUDIO_LOCK_OWNER`. Give builder tasks a lane (`--lane <folder>` or `npm run task -- lane <ID> <folder>`): a builder without one holds the whole game. `npm run task -- holds` shows what can't start and why.
20. In the Prototype sprint pace (`npm run mode`), you are the one accountable lead: split the game into folders first and give every builder a lane; merge a builder's work only when the gate that plays the game passes and you looked at its before/after frames (`npm run shot`); queue no Director check per task (the Director reviews at the end of the phase); and point the game dev at the Arcade early, because a phase only closes when a person plays a build and says it's fun (`npm run verdict`).
